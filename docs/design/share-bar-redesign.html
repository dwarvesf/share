Share Bar, redesigned for members

The menu bar client for share, rebuilt as a popover. One line says whether anything needs a hand; a route line shows which machines serve this hostname; every link sits under the machine that holds it. Revision 2, after two rounds of the kit's six-lens critique.

Scenario

Popover appearance

Try it with the keyboard

  • Arrow keys move through rows; Return copies.
  • Delete removes; focus moves to Undo, and Command Z also undoes while the note is up.
  • Left and right arrows switch tenants on the tab strip.
  • In a member's menu, arrows move and Esc closes.

Needs a look counts only what an admin can act on: an offline machine, a paused member, an expired code, a member who left. An invited member is information, not an alert.

Copy flashes on the row itself. Copying a link whose machine is offline says so, because the visitor would get a 503.

The state machines behind these screens

An audit of bin/share, the Share Bar and SPEC-009 found 19 state machines that live only as flag combinations, file presence or prose. Six can cause a wrong action today. The fix is five shared mechanisms, not nineteen separate ones, and nothing on disk or on the wire changes shape.

MachineWhat goes wrong todayDecision
Member status (SPEC-009)After rotate the member must join again, but join only accepts invited, so every rejoin failsOne transition table owns every status; rotate ends at invited and join restores the earlier status
Multi-step commandsA setup --r2 that dies after the config write reports R2 on, and new cloud links 404A step journal: status and the Share Bar say "stopped at step 13; rerun this"
Profile roleAfter migrate the bar shows Stopped with a Start button that cannot workOne role function; a migrated profile reads as not set up
Link state per rowExpired links stay copyable; a link whose login gate vanished turns public silentlylink_state on every row: live, expired, shadowed, gate missing, revoked, paused
Join progress (SPEC-009)Resume guesses the step from which files exist; a wrong guess spends the one-time codeJoin records its step and resumes from it
Config fileA setup rerun drops keys it does not own; on a members tenant it would drop members=on and its safety refusalsEvery writer keeps keys it does not own

Shared across all three audiences. share state stays schema 1 and only gains keys, so the shipped Share Bar keeps working. Every refusal gets a stable code and a next command, so a person reads the sentence, the bar shows a copyable fix, and an agent reads the code. Agents read state only from share state, never from the human status text.

Calls for your review

Popover instead of the native menu. A menu cannot hold chips, presence or a route line. The cost is rebuilding the keyboard path the menu gave for free; this prototype shows it. Keep the old menu as a fallback for one release?

Group links by the machine that holds them. The alternative is one flat list by date with an origin column. Grouping makes "An's MacBook is offline, 2 links wait" obvious; a flat list finds one name faster.

Start and Stop move into the gear menu. They are rare, and the space goes to the route line. A stopped origin still shows in the strip as something that needs a hand.

Undo before the CLI runs. Remove waits while the note is up, then calls share rm. Removing a member's link only revokes it, so the file on their machine survives either way.
