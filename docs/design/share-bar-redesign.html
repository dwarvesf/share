Share Bar, revision 6: menu polish

The menu shows your recent links and nothing else. Team status, members and machines move to Settings. A single line at the bottom appears only when something needs a hand. Built for a team of ten or more. Revision 5 rebuilds Members and Tenants on the pattern real team tools use (a row menu instead of a button bar, a source list instead of a table) and was checked in 20 screenshotted states, light, dark and narrow. Every button runs its real workflow: open Settings and try Tenants and Members, right-click a link, or pick First run.

What changed in revisions 3 and 4

The menu answers one question

  • "Where is the link I just shared?" Recent links, newest first, with search. Nothing is grouped by person.
  • Mine is the default; Team shows everyone's recent links with the owner in the meta line.
  • Each row has one meta line: who, where it lives, and expiry. A state word appears there only when the link does not answer.

Status became one line

  • No status header, no route line, no strip. When all is well, the footer says "All links answer" in gray.
  • When something needs a hand, the footer says "2 need a look" in orange. Clicking it opens a short list with one action each.
  • The menu bar icon gets a small dot, nothing more.

Settings holds the rest

  • General: launch at login, default expiry, default storage, copy format, notifications.
  • Tenants: every hostname, your role, the machine that serves it, start and stop.
  • Members (admins): a searchable table that works for 12 or 50 people, invite, pause, rotate, remove.
  • Advanced: CLI path, logs, the legacy menu.

Gaps the mapping found, and the decisions

GapDecision
The menu itself had no state machineSwift PopoverState: list, issues, publishing, drop target, undo; one reducer, one test per move
"Add tenant" had no meaningTwo paths: join with a code (R0 to R7) or set up a hostname (R0 to R2), both journaled
The app cannot run admin commands: the admin token lives only in the shell environmentNew config key admin_token_cmd, a command, never the token; empty means Share Bar asks each time and never stores it
A member removed while offline had no state"You were removed" with Clean up (leave --local)
Long admin commands from the app need stop and resumeStop ends the process; the journal keeps the step; the tenant shows Resume or Roll back
Removing a members tenant had no answerRefused with code members_present and a link to Members
Cloud storage and members were command-line onlyButtons in the tenant detail, admin only, journaled
First run had no designThe two Add paths, shown in the menu
Link actions beyond copy were undefinedRight-click menu, items shown only when the link state allows them
Member buttons had no ruleEach button reads the D8 table; a dimmed button says why

Calls for your review

Mine as the default scope. A member mostly needs their own links. Admins can switch to Team; the choice is remembered.

Members and machines live only in Settings. The menu never lists people. An offline member shows up only through the footer line, and only for admins.

Eight recent links, then "Show all". Show all opens the full list in a window with the same search; the menu stays short.

Settings window instead of submenus. Tenants, members and start/stop are rare tasks; a window is easier to scan and works with the keyboard.
