## What worked

- Independent verification found real bugs the builders missed: the verifier caught the double `share:` prefix and the debug entry shipping in release; the fresh re-audit caught an untested floor rule (a rounding mutant survived 59 tests).
- The security lens plus a refuter found a pre-existing HIGH: a folder name with newlines forged an index row that could serve the whole home folder. The refuter reproduced it end to end before any fix, so the fix was not argued, only applied.
- The real end-to-end run (app against the real CLI, not a stub) found the one bug no unit test could: the spawned server inherited a blocked SIGTERM from a GCD thread, so Stop Sharing hung.
- Design critique before the build changed the contract cheaply: `share state` became its own verb because an older CLI would have pruned on `status --json`.

## What hurt

- Three spec validation rounds each found a new edge in existing concurrency code; the third critical needed the operator's override to start building. Validation kept finding real issues but with diminishing returns once the design was settled.
- Parallel verifiers ran the fixed-port bash suite at the same time and produced false failures twice, costing re-runs and one confused verdict.
- GUI checks through System Events leaked keystrokes into the frontmost Orca app three times (a typed path became a prompt in another Claude session), despite written rules. `tools/menubar-shot` itself sends a global Escape.
- Bash 3.2 compatibility was proven only by `bash -n`; CI's macOS runner uses the stock 3.2 at run time and failed on `mapfile`. A test also passed the full `uname -n`, which works on the Mini and fails on a dotted runner hostname.
- A shared scratch folder let one worker's commit message file overwrite another's, which led to an amend.
- The 1Password field label in memory was wrong, so the release took four attempts to fetch the notary key.
